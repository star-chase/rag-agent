# 面试终稿

先把三块说顺：开场、提问怎么走到答案、评测数字。缺陷等对方问「你改过什么」再展开。下面是口语句，可以看一遍，然后合上用自己的话讲。

## 开场

这是一个面向企业知识库的问答后端。用户把制度文档上传进来，系统异步解析、分块、向量化。提问时做混合检索：向量一路、关键词一路，用 RRF 合成，再交给大模型，回答里用 `[1][2]` 标来源。

技术栈是 FastAPI、PostgreSQL 16 加 pgvector、Redis、Celery。没有用 LangChain。嵌入模型是豆包的 `doubao-embedding-vision-251215`，输出 1024 维。分块 800 字，重叠 100，最后交给模型的段落是 5 段。

## 上传

小王上传时，接口先确认这个知识库属于小王，别人的库返回 404。文件只收 txt、md、pdf，空文件 400，超过 10MB 返回 413。然后生成对象键，把原文放进对象存储，数据库插入一条 pending 记录并提交，再把任务交给 Celery。

Worker 里是 `process_document`：下载、解析、`chunk_text`、`embed_texts`、删掉这篇文档的旧块、写入新块，状态改成 ready。ready 之后清掉这个库的问答缓存，避免还回放旧答案。

## 提问

以流式为例，入口是 `ask_stream`。

先 `check_rate_limit`。Redis 有序集合保留最近 60 秒，默认 30 次，超了返回 429。Redis 不可用就打 warning 并放行。然后 `get_conversation`，会话必须是当前用户的，否则 404。

接着 `_require_owned_kb`。知识库被删或者不是自己的，404。这一步在读缓存之前，因为缓存键里没有用户 id。

缓存键是 `qa:{知识库id}:{问题的 MD5}`。问题先去掉首尾空白再转小写。命中就存下用户和助手两条消息，回放 `sources`、一条 `delta`、`done`，`cached` 为 true。不检索，也不调模型。

未命中走 `search_knowledge_base`。`embed_query` 把问题变成 1024 维向量。向量和关键词各取 10 条。关键词用 `pg_jieba` 的 `jiebacfg` 切词，词和词 OR 连接，按 `ts_rank` 排序。`_rrf_fuse` 两路各自从第 1 名计分，先留 10 条。然后算余弦相似度，等于 1 减余弦距离。真实向量低于 0.35 的丢掉。一个都不剩，就回答「知识库中没有相关信息」，不调用模型。还剩下的，默认 `rerank_mode=rrf`，再切到 5 条，不再为了排序调一次模型。

有结果才 `build_messages`，系统提示里放 `[1][2]` 和片段正文，然后 `chat_stream` 推 `delta`。结束时写入缓存，TTL 一小时。

## 评测

语料是 12 篇制度文档、24 道题，其中 18 道能回答，6 道不能回答。

2026-11-04 用真实嵌入跑过一遍。问句是完整中文。18 道能回答的题，关键词和混合检索的 Recall@5、MRR@5、nDCG@5 都是 1.000。6 道不能回答的题，混合零命中率是 0.667，也就是 4 道被 0.35 拒掉了。还有两道过了阈值：「婚假和陪产假」召回了请假制度，「通勤班车」召回了 FAQ。0.35 是起点，不是标定出来的最优值。

改这些代码之前有一份假向量报告，混合 Recall@5 是 0.778，不能回答的题混合零命中率是 0。那份只说明当时为什么要改，不能说成现在的成绩。这次报告里的引用覆盖率 1.000 也不能当成生成质量，因为对话模型当时是 fake，模板会自己补上 `[1]`。

混合检索单题大约 2.7 秒，慢在每次都要请求嵌入接口。关键词检索在数据库里，大约 7 毫秒。

## 你改过什么

对方问到再按这个顺序说。都已经改完，不要说成代码里还留着。

第一，RRF。以前把两份名单接成一个列表再编号，关键词第 1 名接在向量名单后面，同样的名次权重变小。现在每一路从第 1 名单独加 `1/(60+名次)`。两路都是第一的块，分数是 `2/61`。

第二，中文关键词。以前用正则收成一整段汉字再 `ILIKE`。官方 pgvector 镜像没有中文分词，我在 Docker 里基于 PostgreSQL 16 编译了 `pg_jieba`，配置名是 `jiebacfg`，按 `ts_rank` 排序。应用层没有再装一套 jieba。分词发生在查询时，旧文档不用为了这一条重新入库。「几点上班」和「九点到十点」没有共同词，关键词路仍然召回不到，这种改写靠向量。

第三，拒答。以前只要库里有块，向量路就会返回最近的几段，拒答只靠提示词。当时那 6 道不能回答的题，混合零命中率是 0。现在用余弦相似度，不用 RRF 那个大约 0.03 的名次分。假向量没有语义，fake 模式把阈值关掉。

第四，分块。`chunk_size or 800` 会把传入的 0 吞掉。重叠大于等于块长时会卡死，或者静默丢掉中间。现在只有参数是 `None` 才用默认值，并且要求 `0 <= overlap < chunk_size`。

第五，限流和精排。限流以前是自然分钟，12:00:50 打满，12:01:01 又是一把新键。现在是 60 秒滑动窗口，一段 Lua 里先删过期记录，没超限才写入。Redis 挂了放行并打 warning。`rerank_mode=llm` 时，以前每个片段串行打分，「0-10 分，我给 8」会被解析成 0。现在一次把全部片段交给模型，只接受长度刚好的 JSON 数组，解析失败就保留 RRF 顺序。默认仍是 `rrf`。

还有会话归属。上传会查主人，创建会话以前不查，带上别人的库 id 就能问。现在创建会话、普通提问和流式提问都查。不是自己的库返回 404，不返回 403。提问时的检查在读缓存之前。

## 追问时再补的一句

| 对方问 | 只补这一句 |
| --- | --- |
| 为什么混合检索 | 向量吃改写，关键词吃专有名词和数字。两路都从第 1 名计分，再相加 |
| 为什么不是 2048 | 这个模型可以出 1024 或 2048。`vector` 的 HNSW 最多 2000 维，所以用 1024，索引是 `vector_cosine_ops` |
| 换嵌入模型要做什么 | 向量空间变了，列宽也要改，旧向量不能留，整库重新嵌入 |
| 缓存会不会脏 | 键是库 id 加问题 MD5。文档 ready 或删除时按库删掉 `qa:{库id}:*` |
| 0.35 还能怎么调 | 现在漏过的是婚假和通勤班车。再抬高会拒掉本来能答的题，所以还没标成最优 |
| 生成质量测了吗 | 没有。Recall 不依赖对话模型。要看会不会拒答、会不会自己标 `[1]`，需要接真实 LLM，这次没跑 |
| 代码在哪 | RRF 看 `_rrf_fuse`，关键词看 `_keyword_search`，阈值看 `_min_similarity`，归属看 `_require_owned_kb` |

- 别说「企业级」。说「面向企业知识库」。
- 别说创建会话本来就会查主人。说以前没查，现在创建和提问都会查。
- 别说装了 `zhparser`。是 `pg_jieba`，配置名 `jiebacfg`。
- 别说「几点上班」已经能靠关键词命中「九点到十点」。
- 别说 0.35 是测出来的最优阈值。
- 别把 0.778 说成改完之后的成绩。那是改之前的假向量结果。
