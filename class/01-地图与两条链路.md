# 第 1 课：地图与两条链路

## 这课结束要能说出口的话

「用户上传文档后，API 只负责存文件和写一条 pending 记录，解析和向量化交给 Celery。用户提问时，API 自己做检索和生成。两条线分开，是因为摄入要几秒到几分钟，不能卡在一次 HTTP 请求里。」

## 这个系统在做什么

用户把公司制度传进去。之后用一句人话提问，系统从这些制度里找出相关段落，让大模型根据这些段落回答，并在回答里标 `[1]`、`[2]`。标号能点回原文段落。

模型的权重里没有这家公司的年假规定。规定在数据库里。每次提问都先把相关段落找出来，再交给模型。模型负责组织句子，事实来自找出来的段落。

核心的分块、混合检索、RRF 是这个仓库自己写的，没有用 LangChain。面试时可以指着函数讲，不用把责任推给框架。

## 两条线，不要并成一条

用一次具体操作来记。

### 线 A：上传（慢，用户可以关掉页面等）

小王上传 `leave-policy.md`。

1. API 确认这个知识库属于小王。别人的库返回 404。
2. 检查后缀是 txt、md、pdf 之一，文件不是空的，不超过 10MB。
3. 生成对象键 `kb/{知识库id}/{一段uuid}/{文件名}`，把原文件放进对象存储。
4. 数据库插入一行 `Document`，状态是 `pending`，然后 `commit`。
5. 调用 [`process_document_task`](../app/workers/ingest_tasks.py#L19)`.delay(文档id)`，把活交给 Celery worker。
6. HTTP 响应马上返回。此时通常还没有向量。

Worker 之后才做：下载、解析、分块、向量化、写入 `Chunk`，状态改为 `ready`。失败则改为 `failed`。

对应代码：[`upload_document`](../app/api/routes/documents.py#L25)，然后是 [`process_document_task`](../app/workers/ingest_tasks.py#L19)，真正的流水线在 [`process_document`](../app/services/ingest_service.py#L82)。

本地如果设置了 `CELERY_TASK_ALWAYS_EAGER=true`，API 会在这次请求里直接 `await process_document`。那是没有 Redis 时的调试开关。讲生产流程时，说任务交给 worker。

### 线 B：提问（快，用户在等）

小王问「年假有多少天」。

1. 用问题文本和知识库 id 拼一个 Redis 键，先看缓存。命中就直接返回上次的答案。
2. 没命中：把问题变成向量，同时用关键词去数据库里找段落。
3. 两路结果合成一个名单，取前 5 段。
4. 把这 5 段写进系统提示，调用大模型。
5. 用 SSE 把引用和文字推给浏览器，并把答案写入 Redis，1 小时后过期。

对应代码：[`ask_stream` 路由](../app/api/routes/conversations.py#L62)，业务在 [`chat_service.ask_stream`](../app/services/chat_service.py#L170)，召回在 [`search_knowledge_base`](../app/services/rag_service.py#L120)。

上传和提问共用一个数据库，但不是同一次请求。提问只读已经是 `ready` 的块。`pending` 的文档还没有块，检索看不到它。

## 四个组件各管什么

| 组件 | 这个项目里它存什么 | 一句话 |
| --- | --- | --- |
| PostgreSQL + pgvector | 用户、知识库、文档、分块、向量、会话 | 业务数据和向量在同一个库，删知识库可以级联删掉块 |
| Redis DB 0 | 问答缓存、每分钟限流计数 | 丢了可以重算，服务仍能回答，只是变慢 |
| Redis DB 1 / 2 | Celery 的任务队列和结果 | 和缓存分开，避免清缓存时把任务清掉 |
| Celery worker | 不存数据，只执行摄入 | API 进程不解析 PDF |
| 对象存储 | 原始文件 | 数据库里只存 `storage_key`，不存 PDF 字节 |

对象存储有两种后端。`storage_backend=local` 时写到本机 `uploads/`。`s3` 时写到 MinIO。docker-compose 里强制用 `s3`。

## 先记住的数字

这些都在 [`app/config.py`](../app/config.py#L7)。

| 名字 | 默认 | 含义 |
| --- | --- | --- |
| [`chunk_size`](../app/config.py#L59) | 800 | 一个块的目标长度，单位是字符。先按空行分段，再尽量合并到不超过 800 |
| [`chunk_overlap`](../app/config.py#L60) | 100 | 某一段长过 800、必须硬切时，下一块往回退 100 个字符。多出来的向量化成本大约是 100/800 = 12.5% |
| [`top_k`](../app/config.py#L56) | 5 | 最后交给模型的段落数。向量和关键词各自先取 10 条（`top_k * 2`），融合后再截到 5 |
| [`embedding_dim`](../app/config.py#L41) | 1024 | `doubao-embedding-vision-251215` 的输出宽度。请求里的 `dimensions` 用这个数。列是 [`vector(1024)`](../app/db/models/chunk.py#L31) |
| [`embedding_batch_size`](../app/config.py#L65) | 16 | OpenAI 兼容接口一次最多 16 段。豆包多模态一次只向量化一段 |
| [`rate_limit_per_minute`](../app/config.py#L64) | 30 | 每个用户每分钟 30 次提问 |
| JWT 有效期 | 1 天 | [`access_token_expire_minutes`](../app/config.py#L26) = 60 * 24 |

`embedding_dim` 不是「越大越聪明」。它是所选模型的输出宽度，也会作为豆包请求里的 `dimensions`。这个模型只接受 1024 或 2048。2048 超过 pgvector 对 `vector` 建 HNSW 的 2000 维上限，所以用 1024。换成别的模型，这个数和数据库列要一起改，旧向量要整库重嵌。

## 两套键，不要混

上一课第 3 问答偏了，因为仓库里有两套都带 `kb_id` 的字符串，职责不同。

**问答缓存键**，在 [`_cache_key`](../app/services/chat_service.py#L18)：

```text
qa:{知识库id}:{md5(问题去掉首尾空格并转小写)}
```

同一个问题在两个知识库里答案可能不同。键里没有知识库 id 时，A 库算出的答案会被直接回给 B 库。

**原文件的对象键**，在 [`make_storage_key`](../app/services/ingest_service.py#L139)：

```text
kb/{知识库id}/{uuid}/{文件名}
```

UUID 保证两次上传同名文件不会互相覆盖。这和缓存无关。

**重试时不产生重复块**，靠的是第三件事：[`process_document`](../app/services/ingest_service.py#L82) 写入新块之前，按 `document_id` 删除旧块。那也不是缓存键。

## 一分钟自述（可以背结构，用自己的句子说）

面向企业知识库的问答后端。用户上传文档后，系统异步完成解析、分块、向量化。提问时走混合检索：向量一路、关键词一路，用 RRF 合成，再交给大模型生成带 `[1][2]` 的回答。技术栈是 FastAPI、PostgreSQL/pgvector、Redis、Celery。分块和检索是自己实现的。评测用 12 篇制度、24 条问题，其中 18 条能回答、6 条不能。离线评测里混合检索的 Recall@5 是 0.778。不能回答的问题几乎总会召回一段不相关的内容，拒答目前只靠提示词，下一步是加相关性阈值。

「企业级」这个词先不用。后面会被追问多副本、监控和 SLA，那些还没做。

## 三问的标准答案

**API 做了什么，worker 做了什么。** API 做校验、存原文件、插入 `pending` 文档、提交事务、投递任务。Worker 做下载、解析、分块、向量化、删旧块、写新块、把状态改成 `ready` 或 `failed`。必须先 `commit` 再投递：worker 用另一个数据库会话，事务没提交时它可能查不到这行，日志是 `document not found, skip`。

**为什么两路一起用。** 向量找意思相近的段落。关键词找字面上连续出现的词，例如专有名词、编号、原句。只留向量时，「堡垒机」这种短而精确的词可能被语义上接近、但并不是该词的段落挤掉。

**缓存键为什么带知识库 id。** 见上面「两套键」。答案按库隔离。不带 `kb_id` 会把一个库的答案串到另一个库。
