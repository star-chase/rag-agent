# 第 5 课：谁能看这份知识库

检索和生成讲的是「答得准不准」。这一课讲「谁有资格问、问太快怎么办、同一个问题要不要再算一遍」。

## 这课结束要能说出口的话

「登录发一个 1 天的 JWT，`sub` 是用户 id。访问知识库和文档时按 `owner_id` 过滤，别人的资源返回 404。问答缓存键是 `qa:{知识库id}:{问题的 md5}`，1 小时；文档 ready 或删除时会清掉这个库的缓存。限流是每个用户最近 60 秒 30 次，Redis 有序集合。创建会话和提问都会检查知识库归属。」

这一课作业批改时，缓存失效、滑动窗口和会话归属还没改。下面几节保留当时的现象，用来讲「以前是什么样」。现在的说法以 [面试稿](面试稿-缺陷.md) 为准。

## 登录发的是什么

注册时密码只进 [`hash_password`](../app/core/security.py#L10)，数据库存哈希。邮箱重复在 [`auth_service.register`](../app/services/auth_service.py#L11) 返回 409。

登录接口是 [`login`](../app/api/routes/auth.py#L19)，OAuth2 表单，字段名是 `username` 和 `password`。这里的 username 就是邮箱，这样 Swagger 的 Authorize 按钮能直接用。邮箱不存在和密码错误都在 [`authenticate`](../app/services/auth_service.py#L21) 返回 401，文案都是「邮箱或密码错误」，避免告诉别人这个邮箱有没有注册。账号 `is_active` 为假时返回 403。

通过之后 [`issue_token`](../app/services/auth_service.py#L34) 调用 [`create_access_token`](../app/core/security.py#L21)`(str(user.id))`。令牌里有三块：

| 字段 | 值 |
| --- | --- |
| `sub` | 用户 id 的字符串 |
| `exp` | 现在加 1 天（[`access_token_expire_minutes`](../app/config.py#L26) = 1440） |
| `iat` | 签发时间 |

算法是 HS256，密钥是 [`jwt_secret`](../app/config.py#L24)。默认值 `please-change-me` 只适合本机。没有刷新令牌，也没有一张「作废名单」。用户被禁用后，下一次请求仍会查数据库：[`get_current_user`](../app/core/deps.py#L16) 发现 `is_active` 为假就 401，不必等令牌自己过期。

之后每个需要登录的接口都写 `Depends(get_current_user)`。它从 `Authorization: Bearer ...` 取出令牌，用 [`decode_token`](../app/core/security.py#L30) 解出 `sub`，再按 id 查用户。令牌损坏、过期、用户不存在，都是 401。

## 404 是为了不透露「有这个 id」

知识库行上有 `owner_id`，定义在 [`KnowledgeBase`](../app/db/models/knowledge_base.py#L14)。[`get_owned_knowledge_base`](../app/core/deps.py#L37) 的条件是：

```text
id = 路径里的 id  并且  owner_id = 当前用户
```

查不到就 404，文案「知识库不存在」。文档也一样，走 [`get_owned_document`](../app/core/deps.py#L51)：先连到知识库，再要求 `owner_id` 是当前用户，否则 404。

小王的库是 7 号。小李已登录，调用 `POST /knowledge-bases/7/documents` 上传文件。查询条件对不上，函数在写对象存储之前就 404。小李分不清「没有 7 号」和「7 号是别人的」。若返回 403，他就知道 7 号存在。

会话的读取也按这个习惯：[`get_conversation`](../app/services/chat_service.py#L69) 要求 `conversation.user_id = 当前用户`，否则 404。

## 创建会话少了一次归属检查

[`upload_document`](../app/api/routes/documents.py#L25) 的参数里用了 [`get_owned_knowledge_base`](../app/core/deps.py#L37)。[`create_conversation` 路由](../app/api/routes/conversations.py#L24) 没有：

```python
return await chat_service.create_conversation(db, user, data.knowledge_base_id, data.title)
```

[`create_conversation`](../app/services/chat_service.py#L54) 只把「当前用户 id」和「请求里带来的知识库 id」写进一行 [`Conversation`](../app/db/models/conversation.py#L9)。不查这库属于谁。

小李因此可以这样做：

1. `POST /conversations`，body 里 `knowledge_base_id = 7`。接口返回 201，会话属于小李。
2. 对这个会话调用 [`ask`](../app/services/chat_service.py#L92)。[`get_conversation`](../app/services/chat_service.py#L69) 看到 `user_id` 是小李，放行。
3. [`search_knowledge_base`](../app/services/rag_service.py#L120) 只按 `knowledge_base_id = 7` 查块，不再看主人是谁。

小李读到小王库里的年假制度。文档接口的 404 没有盖住这条路。面试里这是一个你自己能指到函数的漏洞：修法是创建会话前走同一套 [`get_owned_knowledge_base`](../app/core/deps.py#L37)。

## 缓存：同一个库、同一句话，1 小时内不再算

[`_cache_key`](../app/services/chat_service.py#L18)：

```text
qa:{知识库id}:{md5(问题去掉首尾空格并转小写)}
```

TTL 是 3600 秒，写在 [`_set_cached_answer`](../app/services/chat_service.py#L32)。Redis 连不上时，读缓存当成未命中，写缓存的失败被吃掉，问答继续走数据库和模型。

键里有知识库 id，所以两个库对同一句话可以有不同答案。键里没有用户 id。在「只有主人能问这个库」成立时，这样够用。上面那个会话漏洞成立时，小李和小王会读到同一条缓存，小李还能把答案写进去。

键里也没有文档版本。10:00 问「年假几天」，答案进缓存。10:10 制度改了，块也重新写入。10:20 再问同一句，命中的仍是 10:00 的答案，直到 11:00 过期。修法可以是：文档变为 ready 或被删除时，删掉 `qa:{这个知识库id}:*`。

## 限流：自然分钟，不是滑动窗口

[`check_rate_limit`](../app/services/chat_service.py#L155) 的注释写「滑动窗口」。代码是：

```text
key   = ratelimit:{用户id}:{UTC 的 yyyyMMddHHmm}
INCR key
若这次是 1，EXPIRE 90 秒
count > 30 则 429
```

`202611011200` 这个键统计的是世界时 12:00:00 到 12:00:59 这一分钟里的次数。下一分钟是另一把键，计数从 0 开始。

小王在 12:00:50 已经问了 30 次，第 31 次在 12:00:58，得到 429。12:01:01 的键是新的，这次放行。从 12:00:50 到 12:01:01，大约 11 秒里可以通过 60 次。滑动窗口会看「此刻往前的 60 秒」，这 60 次里的后 30 次会被拒绝。

`EXPIRE 90` 只是让旧键在下一分钟开始后还留 30 秒，避免键永远不删。它不把上一分钟的次数算进这一分钟。

Redis 抛了别的异常时，函数 `pass`，请求继续。这是有意的降级：缓存挂了仍然能回答，代价是限流暂时消失。超过限额的 429 会先被单独抛出，不会被这个 `pass` 吞掉。

## 本课作业

合上讲义，用自己的话写。每题四五句。

1. 小李拿着小王的知识库 id 去上传文档。状态码是什么，为什么不用 403？
2. 12:00:50 已经打满 30 次，12:01:01 再问一次。这次是 429 还是放行？它为什么还不算滑动窗口？
3. 创建会话时查不查知识库主人？小李把 `knowledge_base_id` 写成小王的库之后再提问，检索读到谁的块？
