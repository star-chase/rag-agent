# 面试稿：项目里发现过的缺陷

完整口述用 [面试终稿](面试终稿.md)。这一篇只在对方追问某一条缺陷时展开。五条和会话归属都已经改完。

[`evals/report.md`](../evals/report.md) 是改代码之前的假向量结果：混合 Recall@5 = 0.778，不能回答的题混合零命中率 0.000。[`evals/report-real.md`](../evals/report-real.md) 是 2026-11-04 的真实嵌入结果：混合 Recall@5 = 1.000，不能回答的题混合零命中率 0.667。

## 两分钟，一口气说

这个项目是面向企业知识库的问答后端。我在检索和请求链路上抓过五个问题，加上一个租户漏洞，都已经改到代码里。

第一是 RRF。以前把向量名单和关键词名单接成一个列表再编号，关键词第一名会被向量列表的长度往后推。同样是第一名，两路权重不一样，而且 `top_k` 一改偏差就变。现在每一路从第 1 名单独加 `1/(60+名次)`。两路都是第一的块，分数是 `2/61`。单测是 `test_rrf_ranks_each_channel_independently`。

第二是中文关键词。以前用正则把连续汉字收成一个词，再 `ILIKE`。问「几点上班」，正文写「九点到十点」，这一路是 0 条。官方 pgvector 镜像没有中文分词，我在 Docker 里基于 `pgvector/pgvector:pg16` 编译了 `pg_jieba`。问句和正文都用 `jiebacfg` 切词，词和词之间用 OR，再按 `ts_rank` 排序。应用层没有再装一套 jieba，避免两套词典切出来对不上。分词发生在查询时，旧文档不用为了这一条重新入库。「几点上班」和「九点到十点」没有共同词，关键词路仍然召回不到，这种改写靠向量通道。

第三是拒答。库里只要有块，向量路就会返回最近的几段。当时 6 道不能回答的题，关键词零命中率是 1，混合是 0。拒答只靠提示词。现在在精排之前用余弦相似度过滤，相似度是 1 减余弦距离。默认阈值 0.35，这是起点，还没用评测集标定。假向量没有语义，`embedding_mode=fake` 时这个阈值关掉，否则能答的题也会被拒。过滤后一个候选都没有，就直接回答「知识库中没有相关信息」，不调用模型。RRF 分数只有 0.03 左右，表示名次，没有拿来当阈值。

第四是分块边界。`chunk_size or 800` 会把传入的 0 吞成默认值。`overlap` 等于 `chunk_size` 时硬切的起点退回整段开头，死循环。`overlap` 更大时，中间一段被静默丢掉。现在只有参数是 `None` 才用默认值。`chunk_size` 必须大于 0，并且 `0 <= overlap < chunk_size`，否则抛 `ValueError`。`top_k` 同样只在 `None` 时用配置。单测是 `test_chunk_overlap_bounds`。

第五是限流和精排。限流注释写着滑动窗口，实现是自然分钟。12:00:50 打满 30 次，12:01:01 又是一把新键，大约 11 秒里可以通过 60 次。现在用 Redis 有序集合，一段 Lua 先丢掉 60 秒以前的时间戳，没超限才写入，避免并发下先检查再写入都通过。Redis 挂了仍然放行，并打 warning。`rerank_mode=llm` 时，以前每个片段串行打一次分，「0-10 分，我给 8」会被解析成 0。现在一次把全部片段交给模型，只接受长度刚好的 JSON 数组。解析失败就保留 RRF 顺序并打日志。默认模式仍是 `rrf`，这条只在打开 `llm` 时发生。

还有一个租户漏洞。上传文档会查知识库主人，别人的库返回 404。创建会话以前不查，请求里带上别人的库 id 就能问，检索只按库 id 取块。现在创建会话、普通提问和流式提问都会查 `owner_id`。不是自己的库返回 404。提问时的检查放在读缓存之前。

## 卡片：面试官让你展开某一条

### RRF

以前 `_rrf_fuse` 对 `vector_hits + keyword_hits` 做一次 `enumerate`。向量路有 10 条时，关键词第 1 名的分母从 61 变成 71。现在两路各自 `enumerate(..., start=1)`。向量 `[甲, 乙, 丙]`、关键词 `[丙, 甲]`、`k=60` 时，甲是 `1/61+1/62`，丙是 `1/63+1/61`，乙是 `1/62`，顺序是甲、丙、乙。融合没有完全坏掉，坏的是不该有的偏向。

### 中文关键词

镜像是自己的 `rag-agent-postgres:pg16`，`docker-compose.yml` 的 postgres 服务构建 `docker/postgres/Dockerfile`。`CREATE EXTENSION pg_jieba` 在 [`init_db`](../app/db/init_db.py) 里，测试库同样会建。`jiebacfg` 自己的 `to_tsquery` 会把词用 AND 连起来，长问句会过严，所以先从 `to_tsvector('jiebacfg', 问句)` 取出词元，最多 16 个，用 OR 拼起来，再和正文的 `to_tsvector('jiebacfg', content)` 做 `@@`，按 `ts_rank` 排序。停用词被词典丢掉，不会变成必须命中的词。

这句话要主动说：同义词、没有共同字的改写，关键词路解决不了。阈值也解决不了，那是向量相似度的事。

### 拒答

过滤发生在 RRF 之后、rerank 之前。没有相似度的候选在阈值开启时按 0 处理。空结果不走 [`build_messages`](../app/services/rag_service.py#L157)，也不走模型。流式接口仍是 `sources`（空列表）、一条拒答 `delta`、`done`。拒答会写入 `qa:{知识库id}:{问题 md5}`，TTL 仍是 3600 秒。文档变为 ready 或被删除时，[`invalidate_kb_cache`](../app/services/chat_service.py#L43) 删掉这个库的问答缓存，避免新文档进来后还回放「没有相关信息」。

假向量模式跳过阈值，是因为评测和接口测试用的是哈希向量，余弦可以很低，甚至是负数。用 `>= 0` 也会丢掉假向量命中的段。

### 分块

`overlap=0` 是合法值，必须保留，不能被 `or` 换成默认的 100。`chunk_size=100, overlap=100` 现在抛 `ValueError`。`chunk_size=100, overlap=200` 也抛，不会再悄悄丢掉中间。

### 限流和 llm 重排

窗口是 60 秒，成员是 `时间戳:uuid`，避免同一时刻两次请求写成同一个成员。键过期用 `PEXPIRE`。超限抛 429，这个异常在 Redis 的 `except` 外面，不会被降级逻辑吞掉。

llm 重排失败时 `rerank_score` 沿用 RRF 的 `item.score`，顺序不变。调用方从日志里的 warning 知道精排没做成。

### 会话归属

上传走 [`get_owned_knowledge_base`](../app/core/deps.py#L37)，返回 404，不返回 403，避免告诉对方这个 id 存在。创建会话以前漏了同一次检查。修的时候提问也查了一次：旧数据里可能已经有指向别人库的会话，只拦创建拦不住继续问。缓存键没有用户 id，所以必须在读缓存之前确认库属于当前用户。

## 自述最后一句可以只留这一句

「不能回答的 6 道题，改之前混合零命中率是 0。加上 0.35 的余弦阈值之后，真实嵌入评测里是 0.667，还有婚假和通勤班车两道过了线。0.35 还没标成最优。」

对方追问「还有呢」，再按中文分词、RRF、分块、限流、会话归属往下说。

## 别说成这样

- 别说「企业级」。说「面向企业知识库」。
- 别说创建会话「需要查主人」，听起来像本来就查了。说「以前没查，上传的 404 被绕过了，现在创建和提问都会查」。
- 别说装了 `zhparser`。镜像里编的是 `pg_jieba`，配置名是 `jiebacfg`。
- 别说 0.35 是测出来的最优阈值。
- 别说「几点上班」已经能靠关键词命中「九点到十点」。
- 别把 0.778 说成修复之后的 Recall。
